Moving Banner to Ellucian SaaS: A Practical Migration Plan

A SaaS move changes how you customise, report and integrate. A phased plan that avoids the common surprises.

September 24, 2026 9 min read Cloud

More institutions are moving Banner from on-premises data centres to Ellucian's SaaS offering. The appeal is clear: continuous updates, less infrastructure to run and a smaller patching burden. But SaaS also changes the rules for customisation, reporting and integration, and those changes deserve a plan of their own.

Phase 1: Inventory everything that touches Banner

Start with a complete map of what you have:

  • Local modifications to baseline forms, packages and tables
  • Custom Pro*C, PL/SQL and shell jobs in your job submission queue
  • Direct database connections from reporting tools, scripts and third-party systems
  • File-based feeds in and out (bank files, LMS, ID cards, housing, and so on)

In a SaaS model, direct database access and arbitrary server-side code are generally restricted, so each of these items needs a new home.

Phase 2: Classify and decide

For every item, choose one of four outcomes:

  1. Retire: no longer used or replaced by delivered functionality.
  2. Re-configure: achievable with baseline rules and settings.
  3. Re-build: move to Banner Extensibility, Experience or Ethos APIs.
  4. Re-platform: shift reporting to a supported analytics or data-lake approach.
Expect the inventory to be larger than anyone estimates. Undocumented scripts on a long-forgotten server are a migration classic.

Phase 3: Rebuild integrations on APIs

Integrations that used to read tables directly should move to Ethos APIs and change notifications wherever possible. This is real work, but it pays off: API-based integrations survive upgrades far better than database-level ones.

Phase 4: Rehearse the cutover

Plan at least two full mock migrations with data validation scripts that compare record counts and key balances between source and target. Time each rehearsal, because that becomes your cutover window estimate.

Phase 5: Hypercare and new operating model

After go-live, your team's job changes from running infrastructure to managing a service: tracking Ellucian's update schedule, regression-testing delivered changes and owning configuration. Budget for a hypercare period and retrain staff for the new model.

Migrating to SaaS is not a lift-and-shift. It is an opportunity to pay down a decade of technical debt.
